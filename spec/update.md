# Updating Anchorage

Anchorage updates its own AppImage from Game Mode, so a user never has to go back to Desktop Mode and the installer script. The release that carries the new AppImage is the one `scripts/release-assets.sh` stages (`INT-25`, `INT-28`).

## Requirements

| ID | Requirement | Status | Verified by |
|----|-------------|--------|-------------|
| `UPD-1` | Self-update applies only when Anchorage runs from an AppImage (`APPIMAGE` names an existing file the user can write, in a folder the user can write). From anything else (a Nix build, a checkout, a read-only file) the app shows `Updates come from how you installed it` in place of the update entry and never touches a file. | planned | `test_self_update` (fake `APPIMAGE` paths: writable, read-only, unset) |
| `UPD-2` | Anchorage checks `https://api.github.com/repos/DisposableSoftware/anchorage/releases/latest` for a release newer than its own version (`application/config/version`, compared as numbers: `0.10.0` is newer than `0.9.0`; never a downgrade, never a prerelease or draft). The check runs at start when `[ports] check_updates` is not `false` (at most once an hour, with the port checks), and on `refresh` and the menu entry (`UPD-4`) always. A failed check shows nothing worse than being offline. | planned | `test_self_update` (fake releases: newer, same, older, prerelease, `0.10.0` vs `0.9.0`, failure) |
| `UPD-3` | When a newer release exists, the home screen shows it without taking over: a `Update 0.3.0` chip in the bottom bar next to the name, and a toast once per version per session. The `Update Anchorage to 0.3.0` entry is the first entry of the app menu (`HOME-14`). | planned | `test_home`; screenshot |
| `UPD-4` | Choosing the entry downloads `Anchorage-<version>-x86_64.AppImage` and `SHA256SUMS` of that release (GitHub release assets of `DisposableSoftware/anchorage` only, over HTTPS, the redirect rules of `PORT-13`) next to the running AppImage as `Anchorage.AppImage.new`, with progress and cancel (`back`), never blocking the main loop. The size is at most 200 MiB and must match the release's `size`; the SHA-256 must match the line for that file in `SHA256SUMS` and the asset's API `digest` when the release lists one. A mismatch deletes the download and shows `Could not update “Anchorage”` with the reason. | planned | `test_self_update` (fake HTTP: success, bad hash, wrong size, missing line, cancel, foreign host) |
| `UPD-5` | Before it replaces anything, Anchorage checks that the download is an AppImage that starts: the ELF header, the AppImage type 2 magic, the executable bit set, and `--appimage-version` answering with status 0 within 10 seconds. A download that fails any of these is deleted and the running AppImage stays untouched. | planned | `test_self_update` (fake files: not ELF, no magic, a script that hangs, one that fails) |
| `UPD-6` | The swap is a single `rename` of `Anchorage.AppImage.new` over the AppImage path, so the running copy keeps working and a power loss leaves either the old file or the new one, never a partial one. The old file is kept as `Anchorage.AppImage.previous` until the new version has run for 10 seconds, then deleted, and the next start removes a stale one. The Steam shortcut, its ID and artwork stay valid because the path does not change. | planned | `test_self_update` (rename semantics on temp files, previous cleanup) |
| `UPD-7` | The installer's record of the files it wrote (`~/.local/state/anchorage-installer/files.sha256`, `INT-33`) is updated with the new AppImage's hash after a swap, so a later `install-steamos.sh` rerun sees the same version as current and `--uninstall` still removes the file. | planned | `test_self_update` (record before and after); `scripts/manual/steam-install.sh` (a rerun after a self-update changes nothing) |
| `UPD-8` | No update starts or swaps while an install, an update or a launch is busy, or while a port is running; the entry says `Finish what is running first` and the download waits for the queue. The update never touches ports, their data or the state. | planned | `test_self_update` (busy and running ports) |
| `UPD-9` | After the swap Anchorage offers `Restart now` and `Later`. `Restart now` starts the new AppImage with a detached `/bin/sh` that waits for this process to end (same environment, no AppImage variables of the old process), then quits cleanly. If Steam counts the app as ended, opening it again from the library works, and the dialog says so. `Later` leaves the new version for the next start. | planned | `test_self_update` (the spawned command line and environment); manual on a Deck |
| `UPD-10` | The release notes of the newer version are not fetched or shown (the chip and the entry name only the version number), so no text from a release is rendered by the app. | planned | `test_self_update` |

## Implementation notes

- `app/src/self_update.gd` holds the logic (check, download, verify, swap, restart command) so it can be tested with fake HTTP and temp files; `ports.gd` or `home.gd` only wire it to the UI (`ports.self_update_info()`, `ports.update_self()`, `ports.restart()`, `notice_changed`).
- The running AppImage is a mounted squashfs (or an extraction directory under `APPIMAGE_EXTRACT_AND_RUN`); replacing the file by `rename` does not disturb it. Never write into the file in place.
- Trust is the same as for the port catalog (`spec/ports.md`, "Catalog updates"): a release of this repository, over HTTPS, checked against its own `SHA256SUMS` and the API digest. That guards against corruption and a wrong download; it does not protect against a malicious release.
- A self-update replaces only the AppImage. Steam artwork, the desktop entry and the installer script change only when the installer is run again.
