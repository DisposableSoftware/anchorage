### Implementation notes: the SteamOS installer

- **Steam's shortcut ID.** Steam ROM Manager and BoilR compute it as `crc32(exe + appname) | 0x80000000`, with `exe` exactly as stored in `shortcuts.vdf` (quoted). The 64-bit ID of the old Big Picture grid is that value shifted left 32 bits, OR `0x02000000`. Shortcuts that the Steam client adds itself often carry an `appid` that does not match this calculation, and Steam then uses the stored `appid` for the grid files. So the script always writes the field, and it reuses the stored value for a shortcut that is already there.
- **`shortcuts.vdf`** is binary KeyValues: `0x00` name NUL starts a map, `0x01` name NUL value NUL is a string, `0x02` name NUL followed by 4 bytes is a little-endian int32, and `0x08` ends a map (also `0x03` float32, `0x07` uint64 and `0x0a` int64). The file is one map, `shortcuts`, with children `"0"`, `"1"`, and so on, and it ends with `08 08`. The script copies every other shortcut's bytes unchanged. It refuses a file it can't parse, and leaves it alone.
- **`steamos-add-to-steam`** (SteamOS, and the `vicrodh/steamos-add-to-steam` replica) URL-encodes a path, touches `/tmp/addnonsteamgamefile` and runs `steam steam://addnonsteamgame/<path>`. That starts Steam when it isn't running, returns before Steam has acted, and lets Steam choose the name and the ID. So the script can't place the artwork after it, and doesn't use it.
- **Steam must be closed.** Steam keeps the shortcuts in memory and writes `shortcuts.vdf` when it exits, so an edit made while it runs is lost. In Desktop Mode on a Deck, Steam is running, so the first run usually stops and asks the user to exit Steam first. The script checks `pgrep -x steam`, and the pid in `~/.steam/steam.pid`.
- **Accounts.** The shortcut goes to every account in `userdata/` (numeric IDs other than `0`), in each Steam folder found: `~/.local/share/Steam`, `~/.steam/steam`, `~/.steam/root` and the Flatpak `~/.var/app/com.valvesoftware.Steam/{.local/share,data}/Steam`, without duplicates after symlinks are resolved. Steam shows only the logged-in account's shortcuts, so this is simpler and more reliable than guessing the account from `loginusers.vdf`. Flatpak Steam can't read `~/Applications` until it is allowed to (`flatpak override --user --filesystem=~/Applications com.valvesoftware.Steam`). The script says so, but doesn't change the permission. An account folder without `config/` is skipped rather than given one: Steam creates `config/` (with `localconfig.vdf`) the first time the account logs in, so a folder without it is a leftover or an account Steam has not set up, and Steam would not show a shortcut there yet anyway.
- **Tools.** SteamOS probably ships python3 (the replica of its `steamos-add-to-steam` uses it), but that is not confirmed, and the script does not need it. The VDF reader and writer and the CRC-32 are bash, `od` and `dd`, and the release JSON is matched with a bash regex. The script runs `exec </dev/null` first, because under `curl | bash`, bash reads the script itself from standard input. Everything is inside `main`, so a download that stops partway runs nothing.
- **Release assets.** `scripts/release-assets.sh` stages the release files in `dist/vX.Y.Z/`: the AppImage, `steam-{portrait,wide,hero,logo,icon}.png` (from `data/steam/`), `io.github.DisposableSoftware.Anchorage.svg`, `install-steamos.sh` with `PINNED_VERSION` set to the release, and `SHA256SUMS` over all of them. The art comes from the release, not from raw files in the repository, so the checksums cover it and the version always matches.
- **Files it wrote.** `files.sha256` (in `sha256sum` format: hash, two spaces, absolute path) lists the AppImage, the icon and each artwork image with the hash they had when the script wrote them, or found them equal to the release's. An artwork image whose hash is neither the release's nor the listed one is the user's (set in Steam's Manage, Customize), and is kept; `--uninstall` removes a file only while its hash is the listed one, then the list. The desktop entry carries its own marker line instead. Old `shortcuts.vdf.anchorage-backup-<time>` files beyond the three newest are deleted after a successful write.
- **Speed.** The VDF reader is bash over one array element per byte: about 5 s for a `shortcuts.vdf` with 1000 shortcuts. The plan made while Steam is checked is kept per account (its edits and the file's size, modification time and inode), and reused at write time when the file has not changed, so each file is read twice (plan, and the check of the new file) instead of three times. curl gives up on a stall with `--speed-limit 1024 --speed-time 60`.
- **Test hooks.** `ANCHORAGE_API_URL` (default `https://api.github.com/repos/DisposableSoftware/anchorage`) and `ANCHORAGE_DOWNLOAD_BASE` (default `https://github.com/DisposableSoftware/anchorage/releases/download`) exist only for `scripts/manual/steam-install.sh`, which serves a fake API and fake assets from localhost.
- Sources: [Steam ROM Manager, generate-app-id.ts](https://github.com/SteamGridDB/steam-rom-manager/blob/master/src/lib/helpers/steam/generate-app-id.ts); [steam_shortcuts_util (BoilR), app_id_generator.rs, shortcuts_writer.rs and testdata](https://github.com/PhilipK/steam_shortcuts_util); [steamos-add-to-steam replica](https://github.com/vicrodh/steamos-add-to-steam); [Valve: Steam browser protocol](https://developer.valvesoftware.com/wiki/Steam_browser_protocol); [ValvePython/vdf](https://github.com/ValvePython/vdf), the test's independent parser.
