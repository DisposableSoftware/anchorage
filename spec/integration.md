# Integration

## XDG / freedesktop

| ID | Spec | Requirement | Status |
|----|------|-------------|--------|
| `INT-1` | Base Directory | Config paths come from `OS.get_config_dir()` (`$XDG_CONFIG_HOME`), and `user://` is `$XDG_DATA_HOME/anchorage` (`application/config/use_custom_user_dir`). State goes to `$XDG_STATE_HOME`, falling back to `~/.local/state`, and cache to `OS.get_cache_dir()`. Nothing is hard-coded as `~/.config`. | done |
| `INT-2` | Desktop Entry | `io.github.DisposableSoftware.Anchorage.desktop`: `Name=Anchorage`, `Exec=anchorage`, `Icon=io.github.DisposableSoftware.Anchorage`, `StartupWMClass=io.github.DisposableSoftware.Anchorage`, `Categories=Game;`. It passes `desktop-file-validate`. | done |

## AppImage

| ID | Requirement | Status | Verified by |
|----|-------------|--------|-------------|
| `INT-25` | Each GitHub release attaches `Anchorage-<version>-x86_64.AppImage`, a self-contained build that runs on SteamOS and other x86_64 glibc Linux without Nix or other installs. The binary is the official Godot release export template (same engine version as nixpkgs' `godot`) with the pack embedded and the Compatibility renderer. It is not patched: no RPATH, no Nix interpreter, and it links only glibc libraries. Everything else (Wayland, X11, GL, Vulkan, audio) is loaded at run time from the host. The system needs only glibc, its drivers, and FUSE 2 (or `--appimage-extract-and-run`, or `APPIMAGE_EXTRACT_AND_RUN=1`, which need no FUSE). The AppImage carries the desktop entry, icon and metainfo. The window title has no "(DEBUG)", the app ID is the one in `WIN-3`, and `user://` and the config paths follow `INT-1`. | partial: the release flow builds and attaches it (`scripts/release.sh`, `/release`) but no release has run yet; not run on SteamOS or under gamescope | `scripts/manual/appimage.sh` (headless sway, extract-and-run and FUSE mount: contents, ELF checks, window, app ID, title, size, quit, empty environment) |
| `INT-26` | `nix build .#appimage` (x86_64-linux only; `scripts/build-appimage.sh` runs it and puts the result in `dist/`) builds that AppImage from a clean checkout with no network except the Godot export templates and the AppImage runtime, both fetched by Nix with pinned hashes. The runtime is a dated release of the static type 2 runtime, and the image is a zstd squashfs appended to it (`appimagetool` is not in nixpkgs and adds nothing needed here). The build fails if the binary has an RPATH, a Nix interpreter or a store path, or if the desktop entry or metainfo does not validate. `scripts/manual/appimage.sh` starts the result headless and checks the window. | done | `nix build .#appimage` (the build checks) and `scripts/manual/appimage.sh` |
| `INT-27` | `data/steam/` holds Anchorage's own Steam library artwork, drawn as SVG sources with rendered PNGs: portrait capsule 600×900, wide capsule 920×430, hero 1920×620, logo (transparent, at most 1280×720) and icon 256×256. It is a flat Catppuccin mocha night harbour (the "harbour" concept chosen by the user: sky, hills, water line, a large anchor breaking the waterline, the name in the sky), made to sit beside the SteamGridDB N64 cover art of the ports, contains no third-party artwork or trademarks, and shares its mark with the app icon (`INT-42`). A script renders the PNGs from the SVGs, and a test checks the sizes and that the transparent logo has an alpha channel. | done (not yet seen in a real Steam client: that comes with `INT-28`) | `scripts/render-steam-art.sh --check` (the committed files match a fresh render from the pinned tools); `test_steam_art` (sizes, opaque capsules and hero, logo alpha and Steam's logo limits, mocha colours only); manual: every PNG looked at, plus mocks of a library row beside two SteamGridDB N64 covers and of the hero with the logo in Steam's default lower-left place, full width and cropped |
| `INT-28` | `scripts/install-steamos.sh` installs Anchorage on SteamOS from Desktop Mode in one command: it downloads the latest release AppImage into `~/Applications/`, verifies the checksum the release lists, marks it executable, adds a desktop entry and icon, and adds a Steam shortcut named Anchorage with the artwork from `INT-27`. It uses `steamos-add-to-steam` when that exists, and otherwise writes `shortcuts.vdf` directly. | planned | `scripts/manual/steam-install.sh` against a fake Steam folder; manual on a Deck |
| `INT-29` | The script computes the shortcut's artwork IDs the way Steam does (CRC32 of the executable and app name, with the high bit set) and puts each image in `userdata/<user>/config/grid/` under that ID: `<id>p` portrait, `<id>` wide, `<id>_hero`, `<id>_logo`, `<id>_icon`. The ID calculation is tested against known vectors. | planned | `scripts/manual/steam-install.sh` (independent VDF parser reads the result); test vectors |
| `INT-30` | The script is safe to rerun and to undo: it backs up `shortcuts.vdf` before any edit, never changes or removes another game's shortcut, refuses to write the file while Steam is running (and says how to close Steam), does nothing when Anchorage is already installed at the same version, and `--uninstall` removes only what it added. It asks no questions when run non-interactively. | planned | `scripts/manual/steam-install.sh` (fake Steam folders: fresh, existing shortcuts, rerun, uninstall, Steam running) |
| `INT-31` | The README's Install section starts with the SteamOS one-liner, `curl -fsSL https://raw.githubusercontent.com/DisposableSoftware/anchorage/main/scripts/install-steamos.sh \| bash`, followed by the Nix instructions and a manual route (download the AppImage, add it to Steam by hand). The script works when piped from `curl`: it needs no checkout, no terminal input, and takes its version and artwork from the release it downloads. The README tells the reader what the command does and where to read it before running it, and the same command appears in the release notes. | planned | manual (README); `scripts/manual/steam-install.sh` runs the script from stdin |
