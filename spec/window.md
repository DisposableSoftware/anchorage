## Implementation notes

- Fullscreen is `Window.MODE_FULLSCREEN`, set in `main.gd` after the window exists (`app/src/window_mode.gd`). In Godot 4.7 the Wayland backend sends the same `xdg_toplevel.set_fullscreen` (no output) for `MODE_FULLSCREEN` and `MODE_EXCLUSIVE_FULLSCREEN`, and reports any fullscreen configure as `MODE_FULLSCREEN`. On X11 both set `_NET_WM_STATE_FULLSCREEN`; exclusive only adds `_NET_WM_BYPASS_COMPOSITOR = 1`. The release build has no display driver set, so Godot tries X11 first and runs on gamescope's Xwayland when `DISPLAY` is set; gamescope's window manager (`steamcompmgr.cpp`) resizes a window with `_NET_WM_STATE_FULLSCREEN` to the root size and otherwise to the size it asked for, which is what letterboxed 0.3.0. Gamescope ignores the bypass hint, so exclusive gains nothing there and would only unredirect on a desktop compositor.
- Under sway's Xwayland the release build's window is marked fullscreen but keeps 1280×720, while the slower debug build is resized, and the same request sent again a few seconds later (`xdotool windowstate --add FULLSCREEN`) resizes the release one too. So sway drops part of a fullscreen request that comes right after the window maps; Godot itself sends it after mapping even for a window created fullscreen (`DisplayServerX11::_create_window`). Gamescope records the state from the request or from the property at map time and re-applies the root size whenever focus is recomputed, so this should not happen there, but only a Deck can confirm it.
- In fullscreen no minimum size is set either: gamescope's output can be smaller than 1280×720 when a lower game resolution is chosen in Steam, and the stretch mode scales the layout down.
- The Wayland app ID comes from `application/config/name` in `app/project.godot`, which is why that setting holds the reverse-DNS ID. The window title is set in `main.gd`.
